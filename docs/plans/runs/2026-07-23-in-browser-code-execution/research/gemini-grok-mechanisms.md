# How Gemini, Grok, Perplexity Labs, and DeepSeek render/execute code artifacts (2026 state)

Research date: 2026-07-24. Grading: **Verified** = fetched/read the source this session. **Inferred** = deduced from something read this session but not stated outright. **Assumed** = convention/training-data recall, not checked this session — flagged explicitly, never presented as fact.

Note up front: none of the four vendors publish a technical architecture doc for their preview sandbox. Nearly everything below comes from official help-center/marketing pages (for feature existence and platform availability) plus third-party reporting, dev forums, and public-suffix-list / bug-bounty domain records (for mechanism). Where I could not find primary evidence, I say so rather than filling the gap from memory.

---

## 1. Gemini Canvas — Web (gemini.google.com)

**Mechanism (Inferred/Assumed — no primary Google architecture doc found):**
- Canvas renders HTML/React previews in-browser inside what public reporting and Google's own domain infrastructure records indicate is a sandboxed iframe, not a server-rendered screenshot. This is **Inferred** from consistent secondary-source description (side-panel "Preview" pane) plus the existence of a dedicated Google sandbox domain family for untrusted user content — see below. I could not fetch a Google document that names the exact iframe attributes or origin used specifically by `gemini.google.com` Canvas, so the precise domain is **Assumed/unconfirmed**, not Verified.
- **Domain family (Verified, but not tied to Canvas specifically):** Google's own `bughunters` domain-tiers list, fetched directly from GitHub, enumerates `usercontent.google.com`, `script.usercontent.google.com`, `usercontent.goog`, `sandbox.usercontent.goog`, and `scf.usercontent.goog` as Google-owned Tier2/Tier4 domains — [google/bughunters `external_domains_google.asciipb`](https://github.com/google/bughunters/blob/main/domain-tiers/external_domains_google.asciipb) (fetched via raw GitHub, Verified this session). The [Public Suffix List PR #1417](https://github.com/publicsuffix/list/pull/1417) (fetched via GitHub API, Verified) shows Google engineer terjanq requesting `*.usercontent.goog` on the PSL specifically so that "every user will have a unique origin under `unique.sandbox.usercontent.goog`" to stop cross-subdomain cookie/data leakage for a new product serving untrusted user content — i.e., this domain family exists *precisely* for the sandboxed-user-content-preview use case Canvas needs. However, **no source I found explicitly names `scf.usercontent.goog` or `sandbox.usercontent.goog` as the literal iframe `src` origin for Gemini Canvas previews** — known confirmed uses of `usercontent.goog` subdomains are `h5games.usercontent.goog` and `playables.usercontent.goog` (Google-hosted web games), per [netify.ai hostname records](https://www.netify.ai/resources/hostnames/79gloe1v4okkg.h5games.usercontent.goog) (Verified this session, but not Canvas-specific). **Gap: could not confirm the exact Canvas iframe origin from a primary/reverse-engineering source this session.**
- **Transpile/execute:** No source found describing a build/transpile step for Canvas's React previews; the pattern is consistent with in-browser ES-module execution rather than a bundler, matching how Google's adjacent product (AI Studio "Build" apps) works (see below) — **Inferred by analogy, not confirmed identical**.
- **Library delivery — confirmed only for the adjacent Google AI Studio product, not gemini.google.com Canvas itself:** Google AI Studio's generated apps use browser `<script type="importmap">` entries pointing bare specifiers (e.g. `react`, `lucide-react`) at `aistudiocdn.com`, which is Google's branded alias/mirror of the `esm.sh` CDN. This is **Verified** via Google's own developer forum thread, [discuss.ai.google.dev "aistudiocdn.com domain alias in Importmap may cause app load failure"](https://discuss.ai.google.dev/t/troubleshooting-tip-aistudiocdn-com-domain-alias-in-importmap-may-cause-app-load-failure/111491), where Google/community troubleshooting explicitly describes `aistudiocdn.com` as "Google's default content domain" for import-map dependency resolution and instructs users to swap in raw `esm.sh` URLs when their network blocks it. A tutorial (egghead.io) separately describes Gemini Canvas ("Gemini 2.5 Canvas") producing React output that, once exported locally, requires manually `npm install`-ing packages like `lucide-react` because "Canvas preview resolves them via CDN while local builds use npm" — **Inferred** that Canvas uses the same import-map/CDN mechanism as AI Studio, but I did not find a source stating the two products share the identical CDN host, so treat "Canvas = aistudiocdn.com" as **Assumed**, not Verified.
- **Service workers — Inferred, not officially documented:** A third-party tool, [Halcao/pwa-packer on GitHub](https://github.com/Halcao/pwa-packer) (fetched, Verified this session), is built specifically to extract "dormant" PWA configuration (`manifest.json`, `sw.js`, embedded in Gemini's HTML output as inert `<script type="text/file">` blocks) and activate it *outside* Canvas by deploying to S3/GitHub Pages/etc. This strongly implies (**Inferred**) that Canvas's preview sandbox does not register/execute service workers even when Gemini writes SW code, consistent with sandboxed same-origin/opaque-origin iframes generally disallowing SW registration. No official Google statement found either confirming or denying this.
- **General iframe restriction behavior (Inferred from aggregated secondary reporting, not a single authoritative doc):** search-engine synthesis (not independently verified against a primary Google doc) describes Canvas previews as blocking direct GPU/WebGL access and flagging `blob:` URL injection as a security violation — this is **Assumed**, sourced from an AI-generated search summary rather than a page I fetched directly, so it should not be treated as confirmed.

**Mobile (iOS/Android) — Verified via official Google Help Center pages, fetched directly this session:**
- Canvas is available in the Gemini mobile apps on both platforms: [Android help page](https://support.google.com/gemini/answer/16047321?hl=en&co=GENIE.Platform%3DAndroid) and [iOS/iPhone help page](https://support.google.com/gemini/answer/16047321?hl=en-gb&co=GENIE.Platform%3DiOS) (both fetched, Verified). Both confirm: you start a Canvas session via the "+"/Add menu → Canvas → prompt; for code/app output there is a **Preview** button that runs the app and a **console** view surfacing errors/logs; edits (manual or via follow-up prompt) auto-save; apps can be pinned to the home screen via "Add to Home Screen."
- Documented **mobile limitations** (Verified, quoted from the help pages): text style/format editing is desktop-only ("is not available on mobile devices"); **shared Canvas links only open at gemini.google.com in a browser — they will not open inside the mobile app**; several content-creation actions (quizzes, infographics, web pages, Audio Overviews, "Add Gemini features") require sign-in and being 18+; Python-to-Colab export is described only via the web interface.
- The mechanism used to render the mobile preview (native WebView vs. something else) is **not stated** by Google's help pages — **Gap**.
- **Inferred/unofficial signal on rollout order:** a November 2025 dev.to post and contemporaneous tech blogs (androidsage.com, winbuzzer.com) reported Gemini 3 appeared first in *mobile* Canvas before web, framed as unannounced "shadow testing" — this is third-party observation, not a Google statement, so graded **Assumed** (unverified by us against a primary source, though multiple independent outlets reported it consistently).

## 2. Grok (grok.com / X) — "Artifacts" / HTML Preview

**Web mechanism — Verified for feature existence/UX, Assumed for underlying sandbox tech:**
- xAI shipped an HTML **Preview** feature on Grok's web app by late February 2025: clicking "Preview" on a code block opens a side sheet with the rendered HTML. Verified via direct fetch of [TestingCatalog's Feb 28, 2025 article](https://www.testingcatalog.com/grok-now-supports-html-preview-making-coding-more-interactive/), which explicitly states the article contains **no technical detail** on sandboxing/iframe/rendering — the feature is described purely at the UX level ("works similarly to Canvas/Artifacts on other platforms").
- This was followed in April 2025 by **Grok Studio**, a fuller canvas-like workspace (documents, code, live preview panel, Google Drive attachment) per [TechCrunch](https://techcrunch.com/2025/04/15/grok-gains-a-canvas-like-tool-for-creating-docs-and-apps/) and [Engadget](https://www.engadget.com/ai/xais-grok-launches-studio-interface-for-documents-and-code-123016714.html) coverage (titles/summaries surfaced via search, not independently refetched this session — **Inferred**, treat as reported-but-not-directly-verified).
- Published/shareable artifacts: secondary sources (ShareDuo comparison blog, surfaced via search, not fetched directly) describe a publish/share flow where the recipient of a shared Grok Studio artifact link needs an X account to view it — **Inferred**, not independently verified.
- **No xAI blog post or technical writeup was found describing the actual sandbox implementation** (iframe `sandbox` attribute, `srcdoc` vs `src`, origin/domain used, CSP). The generic sandboxed-iframe-with-`srcdoc`-and-`postMessage` pattern is the standard industry approach for this kind of live-HTML playground (per a general Medium engineering writeup on building code sandboxes), but applying that pattern to Grok specifically is **Assumed**, not confirmed for this product.
- **Service workers:** no evidence found either way. **Gap.**

**Mobile — mixed/dated evidence, current 2026 status unconfirmed:**
- As of **March 19, 2025**, a TestingCatalog post (fetched, Verified for its own claims) reported: "xAI is working on Artifacts support for the Grok iOS app... Currently, this feature is only supported on web" — i.e., **in development, not shipped**, as of that date.
- Searching for 2026-current status turned up only general model/feature rollout coverage (e.g., [androidheadlines.com's July 2026 Grok 4.5 rollout piece](https://www.androidheadlines.com/2026/07/grok-4-5-rollout-ios-android-web-productivity-features.html), surfaced via search) describing mobile-app support for Excel/PPT/PDF workflows, but **no source found confirming or denying that Grok's iOS/Android apps render/preview HTML or code artifacts as of mid-2026.** This is a genuine **Gap** — the last concrete signal (March 2025) was "web-only," and I found nothing more recent that updates it either direction.

## 4. DeepSeek — HTML/code preview

**No official "Artifacts"/"Canvas" product feature confirmed, as of the sources checked this session:**
- A DeepSeek-V3 GitHub issue explicitly requesting "Artifact/Canvas Support and Native Mobile/Desktop Applications" — fetched directly, Verified — received **no maintainer response** and was auto-closed as `stale`/"not planned": [deepseek-ai/DeepSeek-V3 issue #239](https://github.com/deepseek-ai/DeepSeek-V3/issues/239). This is direct evidence that, at least through that issue's lifecycle, DeepSeek's official product had not shipped a canvas/artifact preview feature and the request went unaddressed.
- "DeepSeek Artifacts," as referenced in some blog titles, refers to a **third-party** community tool built on top of the DeepSeek model (an AI coding assistant generating React/Tailwind apps with a live preview and a "VSCode-like sandbox" for editing) — **not** an official DeepSeek product. Verified via direct fetch of [towardsai.com's "Introducing DeepSeek Artifacts"](https://towardsai.com/p/artificial-intelligence/introducing-deepseek-artifacts), which explicitly frames it as a community-built tool, doesn't name the builder, and is paywalled past the intro.
- Search results otherwise describe DeepSeek's official chat as capable of showing HTML code blocks inline but without a dedicated editable preview workspace; one forum thread reports a user's "Preview" tab showing raw unrendered HTML for a DeepSeek V3-generated calculator, suggesting inconsistent/unreliable rendering even where attempted — **Inferred**, sourced from a forum thread summary, not independently fetched.
- **Gap:** no official DeepSeek documentation on rendering mechanism or mobile support was found (largely because the feature itself doesn't appear to officially exist).

## Distilled summary (~12 lines)

- **Gemini Canvas (web):** in-browser sandboxed-iframe preview (Inferred); Google owns a dedicated `*.usercontent.goog` sandbox-domain family built for exactly this untrusted-content-isolation use case (Verified the domains exist and their stated purpose; **not verified** that Canvas specifically uses `scf.usercontent.goog`/`sandbox.usercontent.goog` — Gap). React/library delivery via browser import maps against `aistudiocdn.com` (an `esm.sh` mirror) is Verified for the sibling **AI Studio** product; applying that to Canvas itself is Assumed/Inferred by analogy only.
- **Service workers in Canvas:** Inferred **not** functional in-preview — a third-party extraction tool exists specifically because Gemini emits "dormant" SW/manifest code that must be pulled out and deployed elsewhere to run.
- **Gemini Canvas (mobile):** Verified full support on iOS and Android per Google's own help pages — Preview button + console, auto-save, home-screen install — with two documented gaps: no desktop-only text-style editing, and **shared Canvas links don't open in the mobile app at all** (web-only).
- **Grok (web):** Verified feature exists since Feb 2025 (Preview → side-sheet render), evolved into "Grok Studio" by April 2025 (Inferred/reported, not refetched). **No primary source on its actual sandbox/iframe/domain mechanism or service-worker use was found anywhere** — treat any such claim as Assumed.
- **Grok (mobile):** last concrete evidence (Mar 2025) says Artifacts were web-only, iOS support "in development." **No 2026 confirmation found either way** — Gap.
- **Perplexity Labs:** Verified to exist (May 2025 launch, multiple outlets), generates shareable-URL web apps/dashboards; said to be available on iOS/Android via search-synthesized help-center content (403 blocked direct fetch), with dashboards/full-app rendering reportedly "more reliable on desktop" (Assumed, unattributable to a specific fetched source). Rendering mechanism (iframe? hosted domain?) undocumented — Gap.
- **DeepSeek:** No official artifact/canvas preview shipped as of the checked GitHub feature request (closed, unanswered, "not planned"); "DeepSeek Artifacts" in the wild is a third-party tool, not DeepSeek's own product.
- **Overall evidence quality:** strong (Verified, official) for Gemini's mobile platform support and DeepSeek's lack of an official feature; weak-to-absent (no primary technical doc for any of the four vendors) for exact sandbox/iframe/domain/service-worker mechanics — this whole area is undocumented by every vendor and only thinly covered by third-party reverse-engineering writeups, none of which fully name-and-confirm a specific product's exact sandbox origin.
